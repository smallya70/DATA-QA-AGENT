PART 2 - ADD DERIVED METRIC DETECTION BEFORE PLANNING
==================================================

Derived metrics must be detected before the planner runs, not after SQL failure.

Build a derived metric catalog per sheet using deterministic rules.

Examples:
1. If quantity and unit_price exist:
   revenue = quantity * unit_price
   sales = quantity * unit_price
   order_value = quantity * unit_price
   gross_sales = quantity * unit_price

2. If revenue/sales and cost exist:
   profit = revenue - cost
   gross_profit = revenue - cost

3. If profit and revenue exist:
   margin_pct = profit / revenue
   profit_margin = profit / revenue

4. If expected_amount and actual_amount exist:
   value_gap = expected_amount - actual_amount
   variance = expected_amount - actual_amount
   shortfall = expected_amount - actual_amount

5. If billed_amount and expected_amount exist:
   billing_gap = expected_amount - billed_amount
   under_billed_amount = expected_amount - billed_amount

6. If total_amount and invoiced_amount exist:
   uninvoiced_amount = total_amount - invoiced_amount
   amount_at_risk = total_amount - invoiced_amount

7. If stock_qty and unit_price exist:
   inventory_value = stock_qty * unit_price
   stock_value = stock_qty * unit_price

8. If stock_qty and reorder_level exist:
   reorder_gap = reorder_level - stock_qty

9. If closed_date and open_date exist:
   resolution_days = closed_date - open_date
   turnaround_time = closed_date - open_date

Also add count-style business metrics:
- record_count = COUNT(*)
- order_count = COUNT(order_id) if order_id exists
- ticket_count = COUNT(ticket_id) if ticket_id exists
- customer_count = COUNT_DISTINCT(customer-like field)
- product_count = COUNT_DISTINCT(product-like field)
- country_count = COUNT_DISTINCT(country-like field)

Store for each derived metric:
- metric name
- formula
- required columns
- confidence
- canonical metric name
- aliases

PART 7 - FIX PROJECTION VS AGGREGATION CONFLICT
==================================================

Projection queries must have precedence over aggregation keyword overrides.

Example bug:
"Show Exception Type and count from Summary Sheet"
was classified as projection, but later "count" triggered COUNT override.

Fix rules:
1. If query_type == projection:
   - do not apply SUM/AVG/MAX/MIN/COUNT auto-corrections
   - treat tokens like count, total, average as potential column names first
2. If a requested token matches an existing column in the selected sheet, prefer projection over aggregation
3. For projection queries:
   - aggregation = None
   - group_by = []
   - answer_type = table

Also fix parser so both requested columns are preserved across "and".
